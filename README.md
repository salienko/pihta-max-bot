# pihta-max

Бот бронирования бани «Пихта» для мессенджера **MAX**. Порт Telegram-бота
[pihta-bot](https://github.com/salienko/pihta-bot) на MAX Bot API.
Python 3.11, aiohttp, asyncpg, PostgreSQL.

Бизнес-логика (правила бронирования, каталог, корзина, предоплаты, таймеры,
резервные копии) взята из pihta-bot без изменений; заменён только транспортный
слой — aiogram → MAX Bot API (вебхук + long polling).

## Переменные окружения

`MAX_BOT_TOKEN` — токен бота из MasterBot / business.max.ru (обязателен).

`DATABASE_URL` — PostgreSQL DSN в секретных настройках хостинга.

`OWNER_MAX_ID` — числовой MAX ID владельца; обязателен при подключении базы.
Узнать свой ID можно командой `/id` в боте.

`WEBHOOK_SECRET` — секрет вебхука (5–256 символов, `A-Za-z0-9_-`), тот же, что
в подписке MAX. На Bothost задаётся вместе с `WEBHOOK_URL`.

`WEBHOOK_URL` — если задан, бот подписывается на вебхук и поднимает HTTP
сервер (`/health`, `/webhook`) на порту `PORT`. Если пуст — работает long
polling (удобно для локальной отладки).

`BOOKING_ENABLED=true` — включать только после проверки подключения базы.

`USE_BRAND` — отправка баннера в карточках (`true` по умолчанию).

## Запуск

```
pip install -r requirements.txt
python main.py
```

На Bothost: шаблон Python / `max-bot`, свой Dockerfile (порт `PORT`),
`internal_port` по умолчанию 3000.

## Что отличается от Telegram-версии

- Главное меню и «reply»-кнопки — инлайн-клавиатуры из `message`-кнопок:
  нажатие отправляет текст кнопки как обычное сообщение.
- «Поделиться номером» — кнопка `request_contact`; контакт приходит
  вложением `contact` (номер разбирается из `vcf_info`), ввод номера
  текстом сохранён как запасной путь.
- `/start` также срабатывает на событие `bot_started`.
- ID пользователя в MAX — это `user_id`, он хранится в тех же колонках,
  что раньше занимал Telegram ID (обычные int64).

## Проверки

`python -m unittest discover` — правила, интерфейс, транспорт.
PostgreSQL-тесты требуют `TEST_DATABASE_URL` (тестовая схема, рабочая база
не используется).

`python smoke_test.py` — вебхук-сервер с замоканным API: health, входящее
сообщение, bot_started, невалидное тело.

## Безопасность

`ca/russian_trusted_root_ca.pem` — корневой сертификат Минцифры, нужен для
TLS к `platform-api2.max.ru` (проверен по SHA-256 отпечатку). Проверку
сертификатов не отключать.

В публичный репозиторий не добавлять базы, снимки, логи, ID владельца и
секреты.
